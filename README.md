# book-shelf

Telegram-бот для поиска FB2-книг в ZIP-архивах. Индексация библиотеки
офлайновая и состоит из трёх шагов — распаковка и разбор метаданных, наполнение
базы SQLite, запуск бота.

```
  data/library/*.zip
          │
          │  ./scan.sh          (разовый контейнер, RW в data/library)
          ▼
  data/library/*.zip.json        ← sidecar с метаданными, создаётся рядом с архивом
          │
          │  ./db-create.sh     (разовый контейнер, читает sidecar'ы)
          ▼
  data/db/db.sqlite3             ← таблица books
          │
          │  ./up.sh            (долгоживущий контейнер bot, читает базу)
          ▼
  Telegram: /start → /author … → /get 1
```

Команды `scan` и `db-create` — одноразовые контейнеры, они не работают постоянно.
Постоянно запущен только бот.

---

## Требования

- Docker Engine **23+** (нужен BuildKit для кэш-монтиров в `Dockerfile`);
- Docker Compose **v2** (используются `name:`, `profiles`, `run --rm`);
- больше ничего: Go, `sqlite3` и `jq` на хосте **не нужны**.

Проверить версии:

```bash
docker version --format '{{.Server.Version}}'   # 23 или новее
docker compose version                          # v2.x
```

## Первичное развёртывание

1. Создать каталоги данных **вручную**:

   ```bash
   mkdir -p data/library data/db
   ```

   Почему вручную: если каталога нет, Docker создаст его сам от `root`, и оператор
   этого не заметит — `./scan.sh` завершится с ошибкой, база останется пустой, а бот
   будет «искать» по пустой базе.

2. Положить `*.zip`-архивы с FB2-книгами в `data/library`.

3. Подготовить окружение:

   ```bash
   cp .env.example .env
   $EDITOR .env      # заполнить как минимум BOT_TOKEN
   ```

4. Выдать контейнерам права на каталоги:

   ```bash
   sudo chown -R 10001:10001 data/library data/db
   ```

   Контейнеры работают непривилегированно от uid/gid `10001`. Если на хосте
   каталоги принадлежат другому пользователю, вместо `chown` задайте в `.env`
   `SCAN_USER_ID`, `SCAN_GID`, `APP_USER_ID`, `APP_GID` — значения должны
   совпадать с владельцем `LIBRARY_HOST_DIR` и `DATA_HOST_DIR`.

5. Собрать образы всех трёх сервисов:

   ```bash
   ./build.sh
   ```

6. Проиндексировать библиотеку — разовый контейнер `scan` распаковывает архивы и
   создаёт рядом с каждым `<archive>.zip.json`:

   ```bash
   ./scan.sh
   ```

   ⚠️ Каталог `data/library` монтируется в этот контейнер **на запись**, а новые
   файлы получают владельца контейнера — подробности в разделе
   «⚠️ Предупреждение: `scan` изменяет каталог библиотеки».

7. Наполнить базу — разовый контейнер `db-create` читает sidecar'ы `*.zip.json` и
   заполняет таблицу `books`:

   ```bash
   ./db-create.sh
   ```

   Без этого шага база останется пустой и бот не найдёт ни одной книги.

8. Запустить бота:

   ```bash
   ./up.sh
   ```

9. Проверить результат:

   ```bash
   docker compose ps        # bot → Up
   docker compose logs bot  # строка "bot started"
   ```

   Затем в Telegram: `/start` → `/author Иванов` → `/get 1`.

## Переменные окружения

Все переменные задаются в `.env` (шаблон — `.env.example`) и не хранятся в git.

| Переменная | Обязательна | По умолчанию | Назначение |
|---|---|---|---|
| `BOT_TOKEN` | да | — | Токен Telegram-бота от @BotFather. Пустое значение — бот не стартует |
| `LIBRARY_HOST_DIR` | нет | `./data/library` | Каталог с `*.zip` на хосте, bind-источник для `/library` |
| `DATA_HOST_DIR` | нет | `./data/db` | Каталог под базу на хосте, bind-источник для `/data` |
| `DB_FILE` | нет | `db.sqlite3` | Имя файла базы внутри `/data` |
| `SCAN_PARALLELISM` | нет | `5` | Сколько архивов `scan` обрабатывает одновременно |
| `HTTP_PROXY` | нет | — | Прокси к `api.telegram.org`. Пусто — прямое соединение |
| `SCAN_USER_ID` / `SCAN_GID` | нет | `10001` | uid:gid контейнера `scan` |
| `APP_USER_ID` / `APP_GID` | нет | `10001` | uid:gid контейнера `db-create` |
| `LOG_LEVEL` | нет | `info` | `debug`, `info`, `warn`, `error` |
| `LOG_FORMAT` | нет | `json` | `json` или `text` |
| `TZ` | нет | `UTC` | Часовой пояс меток времени в логах |
| `COMPOSE_PROJECT_NAME` | нет | `book-shelf` | Префикс имён контейнеров, сети и томов |
| `DB_DSN` | нет | `/data/${DB_FILE}` | DSN SQLite; задавайте, только если нужно добавить параметры |

**Пути внутри контейнеров зафиксированы** в `docker-compose.yml` и не настраиваются:
`/library` — каталог с архивами, `/data` — каталог базы. Независимо меняются только
пути на хосте (`LIBRARY_HOST_DIR`, `DATA_HOST_DIR`).

**Инвариант `DB_DSN`.** Compose сам вычисляет `DB_DSN` как `/data/${DB_FILE}`
(по умолчанию `/data/db.sqlite3`), поэтому хостовые пути менять можно независимо.
Чтобы добавить параметры DSN, раскомментируйте в `.env` строку `DB_DSN`, например:

```bash
DB_DSN=/data/db.sqlite3?_journal_mode=WAL&_busy_timeout=5000
```

`WAL` снимает «database is locked», когда бот читает базу, а `db-create` пишет
в неё. Учтите: `-wal`/`-shm` появятся рядом с базой на хосте.

**Прокси.** В контейнер попадает только `HTTP_PROXY` из `.env`. Экспорт
`HTTP_PROXY` в shell хоста больше не подхватывается, в том числе ботом.

## Скрипты

| Скрипт | Что делает | Когда применять |
|---|---|---|
| `./build.sh` | `docker compose --profile tools build` — собирает образы `bot`, `scan`, `db-create` | после первого клона и после каждого изменения кода/Dockerfile |
| `./up.sh` | `docker compose up -d` — поднимает **только** бота | после `./scan.sh` и `./db-create.sh`, а также после переиндексации |
| `./down.sh` | `docker compose down` — останавливает бота, удаляет контейнеры и сеть проекта | перед обслуживанием хоста; данные (библиотека, база) не трогаются |
| `./scan.sh` | одноразовый контейнер `scan`: распаковывает архивы и создаёт `*.zip.json` | когда библиотека пополнилась или изменилась |
| `./db-create.sh` | одноразовый контейнер `db-create`: читает `*.zip.json` и наполняет базу | после `./scan.sh`, на пустой базе |

`build.sh`, `scan.sh` и `db-create.sh` обязаны передавать `--profile tools`:
сервисы `scan` и `db-create` объявлены с `profiles: ["tools"]`, и без профиля
`docker compose build` / `run` их просто не найдёт. Не «оптимизируйте» это.

Все скрипты:

- требуют `.env` рядом с `docker-compose.yml` (иначе — понятная ошибка и код 1);
- требуют запуска из корня репозитория;
- возвращают код контейнера без потерь (`set -euo pipefail`).

## ⚠️ Предупреждение: `scan` изменяет каталог библиотеки

- монтирует `LIBRARY_HOST_DIR` в режиме **чтение/запись**;
- создаёт рядом с каждым архивом файл `<archive>.zip.json`;
- новые файлы на хосте получают владельца контейнера (`10001`, либо `root`, если
  в `.env` задан `SCAN_USER_ID=0`).

Последствие: каталог библиотеки перестаёт быть «только для чтения». Если он
синхронизируется с внешним источником (rsync,Syncthing, git), sidecar-файлы либо
попадут туда, либо будут удалены, и `./db-create.sh` после этого увидит не всё.
Бот, кстати, монтирует библиотеку только на чтение.

---

## ⚠️ Предупреждение: повторный `db-create` дублирует строки

Причина: вставка идёт как `INSERT INTO books …` — без `UNIQUE`-ограничения и без
upsert-а. Что будет: поиск вернёт дубликаты, а `/get N` может отдать не ту книгу.

**`./db-create.sh` — не команда «обновить индекс».** Полная переиндексация:

```bash
docker compose stop bot          # снять читателей с базы
./scan.sh                        # если библиотека изменилась; иначе пропустить
rm -f ./data/db/db.sqlite3*      # сбросить базу целиком (важно: и -wal, и -shm)
./db-create.sh
./up.sh
```

Если метаданные не менялись, а менялось только содержимое ZIP, достаточно
`docker compose restart bot` — база читается на каждом запросе заново.

## Диагностика

| Симптом | Команда / действие |
|---|---|
| бот не поднялся | `docker compose ps` → ожидается `Exited (1)`; `docker compose logs bot` |
| «нет книг» | `./scan.sh` — искать в выводе `failed to process archive …` |
| каталог кажется пустым | `ls -la data/library`; `docker compose run --rm scan` — путь внутри контейнера |
| прокси не работает | `HTTP_PROXY` берётся **только** из `.env`; экспорт в shell хоста не действует |
| ошибка SQLite | `docker compose run --rm db-create` — код возврата и текст в логах |
| ошибка прав | `ls -ldn data/library data/db` — владелец должен совпадать с `SCAN_USER_ID:SCAN_GID`; текущий uid контейнера: `docker compose run --rm --entrypoint id scan` |
| переустановить | `docker compose down` (Compose v2+: без `-q`) |

Отдельные проверки:

- пустой каталог библиотеки: `./scan.sh` завершится с кодом `1` и сообщением
  `no *.zip archives found …` — это ожидаемо, а не сбой;
- бот переживает 5 неудачных стартов подряд: `restart: on-failure:5`, после чего
  остаётся в состоянии `Exited (1)` вместо бесконечного restart-loop;
- остановка — `SIGTERM`, 20 секунд на завершение; состояние поиска пользователей
  при этом теряется.

Ручная проверка поиска: `/start` → `/author Иванов` → `/get 1`.

## Бэкап и восстановление

Если на хосте установлен `sqlite3`, бэкап безопасен и на работающей базе:

```bash
sqlite3 ./data/db/db.sqlite3 ".backup '/backup/book-shelf-$(date +%F).db'"
```

Если `sqlite3` на хосте нет — остановите бота и скопируйте файл (консистентно,
но бот на это время недоступен):

```bash
docker compose stop bot
cp ./data/db/db.sqlite3 ./data/db/backup-$(date +%F).db
./up.sh
```

Восстановление: положите файл на место `./data/db/db.sqlite3` и выполните
`docker compose restart bot`.

> В корне репозитория лежит старый файл `db.sqlite3` от прежней схемы (FTS5 без
> таблицы `books`). Бот его не использует и во время `docker compose up` не
> откроет: сервисы работают только с `./data/db`. Сохраните его отдельно, если он
> вам ещё нужен.

## Приватность и безопасность

- `.env` не коммитится (см. `.gitignore`), секреты подставляются через
  `docker compose` и **не запекаются в образы**;
- контейнеры работают непривилегированно от `10001:10001`, с `read_only`,
  `cap_drop: ALL` и `no-new-privileges:true`; записываемый `/tmp` — tmpfs;
- боту библиотека монтируется только на чтение;
- состояние поиска пользователей живёт **только в памяти** и теряется при
  перезапуске бота.
