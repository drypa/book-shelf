# ADR-0002. Защита от XXE в FB2-парсере

- **Статус:** Proposed
- **Дата:** 2026-10-08
- **Автор:** software-architect
- **Задача:** [`docs/tasks/fb2-xxe-fix.md`](../tasks/fb2-xxe-fix.md)
- **Затрагивает:** `format/fb2/fb2.go`, `format/fb2/fb2_test.go`

---

## 1. Контекст

FB2-парсер в `format/fb2/fb2.go` использует `xml.Decoder` для разбора FB2-файлов.
Файлы FB2 могут содержать XML-сущности (entitites), которые при несоблюдении
осторожности могут привести к XXE-атакам (XML External Entity).

### 1.1. Угроза

При обработке malicious FB2-файла злоумышленник может:
1. Прочитать произвольные файлы сервера через сущности вида:
   ```xml
   <!ENTITY xxe SYSTEM "file:///etc/passwd">
   ```
2. Выполнить SSRF-запросы к внутренним сервисам
3. Вычислить внешние сущности для скрытого сканирования инфраструктуры

### 1.2. Текущий код

```go
decoder := xml.NewDecoder(reader)
// CharsetReader настроен, но нет защиты от XXE
for {
    tok, err := decoder.Token()
    // ...
}
```

Go's `encoding/xml` по умолчанию **не обрабатывает внешние сущности**, но
для явной защиты рекомендуется:
1. Установить `decoder.Entity = map[string]string{}` (пустая карта)
2. Определить поведение при неизвестных сущностях

## 2. Драйверы решения

| # | Драйвер | Описание |
|---|---|---|
| D1 | Безопасность | Защита от XXE является критической для безопасности |
| D2 | Совместимость | Должны работать обычные FB2-файлы без изменений |
| D3 | Явная защита | Нужно явно отключить обработку сущностей, не полагаться на умолчания |
| D4 | Тестируемость | Решение должно быть покрыто тестами с malicious FB2 |

---

## 3. Рассмотренные варианты

### Вариант A: Отключить обработку сущностей через `decoder.Entity`

**Описание:** Установить пустую карту сущностей, что предотвратит их разрешение.

```go
decoder := xml.NewDecoder(reader)
decoder.Entity = map[string]string{} // Полностью отключить сущности
```

**Плюсы:**
- Минимальное изменение кода
- Стандартный подход в Go
- Явное отключение внешних сущностей
- Сохраняет совместимость с обычными FB2

**Минусы:**
- Внутренние сущности (не внешние) могут вызывать ошибку парсинга

**Оценка:** ✅ Подходит

---

### Вариант B: Игнорировать ошибки разрешения сущностей

**Описание:** Оставить код как есть, полагаться на то, что Go не обрабатывает внешние сущности.

**Плюсы:**
- Без изменений в коде

**Минусы:**
- Непрозрачная защита (полагается на умолчания)
- Не соответствует best practices безопасности
- Риск регрессии при обновлении Go

**Оценка:** ❌ Отклонён

---

### Вариант C: Полная фильтрация через Token callback

**Описание:** Использовать `SetMaxError` или кастомный обработчик токенов для фильтрации Entity.

**Плюсы:**
- Максимальный контроль над процессом парсинга

**Минусы:**
- Сложность реализации
- Не нужно для базовой защиты от XXE

**Оценка:** ❌ Отклонён (избыточно)

---

## 4. Выбранное решение

**Выбрано:** Вариант A

### 4.1. Техническая реализация

```go
decoder := xml.NewDecoder(reader)

// Явно отключаем XML-сущности для защиты от XXE
decoder.Entity = map[string]string{}

decoder.CharsetReader = func(encoding string, input io.Reader) (io.Reader, error) {
    // ... существующая реализация
}
```

### 4.2. Обоснование выбора

1. **Безопасность:** `decoder.Entity = map[string]string{}` полностью отключает
   разрешение XML-сущностей. При встрече сущности парсер вернёт ошибку
   "undefined entity", которую мы обрабатываем как предупреждение.

2. **Совместимость:** Обычные FB2-файлы без сущностей работают без изменений.
   FB2-файлы с внешними сущностями будут отклонены с ясной ошибкой.

3. **Соответствие стандартам:** Этот подход соответствует рекомендациям OWASP
   и рекомендациям Go по защите от XXE.

---

## 5. План изменений

### 5.1. Изменения в коде

1. **format/fb2/fb2.go:**
   - Добавить `decoder.Entity = map[string]string{}` после создания декодера

### 5.2. Тесты

Требуется добавить тест с FB2, содержащим XML-сущности:

```xml
<?xml version="1.0" encoding="utf-8"?>
<!DOCTYPE foo [<!ENTITY xxe SYSTEM "file:///etc/passwd">]>
<FictionBook>
<description>
<title-info><book-title>Test XXE Protection</book-title></title-info>
</description>
</FictionBook>
```

Ожидаемое поведение: парсер не должен читать `/etc/passwd` и должен вернуть ошибку
о неопределённой сущности или спокойно проигнорировать.

### 5.3. Фикстуры для тестов

Создать файл `format/fb2/testdata/book-xxe.fb2` с внешней сущностью.

---

## 6. Критерии приёмки

- [ ] FB2-файл с XML-сущностью не вызывает ошибку чтения (сущность игнорируется)
  или вызывает предсказуемую ошибку о неизвестной сущности
- [ ] Добавлен unit-тест с FB2, содержащим Entity (`<!ENTITY xxe SYSTEM "file:///etc/passwd">`)
- [ ] Обычные FB2-файлы продолжают работать без изменений
- [ ] Обновлена документация (`README.md`) о безопасности парсинга

---

## 7. Влияние на существующее поведение

| Сценарий | До | После |
|---|---|---|
| Обычный FB2 без сущностей | ✅ Работает | ✅ Работает (без изменений) |
| FB2 с внутренними сущностями | Может работать | Может вернуть ошибку (зависит от использования) |
| FB2 с внешними сущностями (XXE) | Риск уязвимости | Защищено |

## 8. Миграция

Изменения минимальны и не требуют миграции данных:
1. Добавить строку кода в `fb2.go`
2. Добавить тест и фикстуру

## 10. Примечания

1. В Go `encoding/xml` по умолчанию не поддерживает внешние сущности, но
   рекомендуется явно отключать их для документирования безопасного поведения.

2. Если FB2-файлы с внутренними сущностями начнут появляться в библиотеке,
   потребуется отдельный анализ необходимости их поддержки.
