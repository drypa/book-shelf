## 2. Блоки работ и параллельность

```
        ┌── T-01 (logging) ──┬──> T-03 (bot) ──┐
        │                    └──> T-04 (scan) ──┤
        └── T-02 (config) ──┬──> T-03          ├──> T-12 (приёмка)
                             └──> T-05 (db-create)┘

        ┌── T-06 (Dockerfile) ──> T-07 (compose+.env) ──> T-08 (скрипты) ──┐
        │                                                                ├──> T-12
        └──> T-15 (CI)                                                   │
                                                                         ├──> T-10 (README) ──┐
        └── T-03,T-05,T-08 ──> T-11 (AGENTS.md) ───────────────────────────┘                    │
                                                                                                  v
                          T-09 (гигиена) ───────────────────────────────────────────────> T-12 (приёмка)
```

**Независимые блоки, которые можно вести параллельно:**

- Блок кода (T-01…T-05) — не требует Docker.
- Блок инфраструктуры (T-06…T-08) — не требует правок Go-кода; собирает текущее
  (исправленное) состояние репозитория.
- T-09 (гигиена) — независим от всего; выполняется первым, чтобы убрать 324 МБ из
  рабочего дерева и не мешать сборке.
- T-13, T-14 — независимы от деплоя.

## 5. Границы задач

**В объёме:** Dockerfile, compose, `.env.example`, скрипты, переименование переменных с
фолбэком, коды возврата, graceful shutdown, логирование в stdout, `.gitignore`, README.

**Вне объёма (осознанно, см. ADR §6):**

- Изменение бизнес-логики поиска, скачивания и сканирования (NFR задачи).
- Идемпотентность `db-create` (`UNIQUE`/upsert/флаг `--reset`) — задокументировано как
  известное ограничение, вынесено в будущую работу (ADR §6, R11).
- Healthcheck-сервиса бота (ADR §6, R18).
- Оптимизация размера образов через distroless (ADR §6, R9) — задача T-17 не входит даже
  в P2.
- Перенос `finder/` — по-прежнему legacy-код без импортеров.

## 7. Что нужно от оператора (вне задач разработки)

1. Создать каталоги `data/library` и `data/db` на хосте.
2. Положить `.zip`-архивы в `data/library`.
3. Подготовить `.env` из `.env.example` и внести `BOT_TOKEN`.
4. **Сделать бэкап текущего `db.sqlite3` вне репозитория** (ADR §8, фаза 0) — до
   удаления артефакта в T-09.

Пункты 1–4 выполняются в порядке, описанном в `README.md` (задача T-10).
