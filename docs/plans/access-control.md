# План работ: контроль доступа к библиотеке (регистрация с одобрением администратора)

Декомпозиция задачи [`docs/tasks/access-control.md`](../tasks/access-control.md)
на основе технического решения [ADR-0003](../adr/0003-access-control.md).

**Статус плана:** утверждён к реализации
**Общая оценка:** ~5 рабочих дней одного разработчика
**Что закрывает:** уязвимость H2 аудита (полное отсутствие авторизации) + H1
(падение бота на не-`message` обновлениях) как обязательная предпосылка.

## 2. Граф зависимостей и параллельность

```
  T-18 (роутер/H1) ──┐
  T-19 (config)     ──┼──> T-21 (guard) ──> T-22 (callback'и) ──> T-23 (docs+приёмка)
  T-20 (users БД)   ──┘                                ^
        └──────────────────────────────────────────────┘
```

- **T-18, T-19, T-20 независимы** — можно выполнять параллельно или в любом
  порядке; каждая самодостаточна и зелёна по `go build/vet/test` сама по себе.
- T-18 можно выпустить в прод **до** остальных: он один превращает бота из
  падающего на `edited_message`/`callback_query` в живой (уязвимость H1),
  не меняя логику.
- Критический путь: **T-20 → T-21 → T-22 → T-23** (~4 дня).

## 4. Контрольные точки

| Точка | Когда | Что проверяется |
|---|---|---|
| **CP-1** | после T-18 | бот не падает на `edited_message`/`callback_query`; `go vet ./...`, `go test ./...` зелёные; поведение одобренного не изменилось |
| **CP-2** | после T-19/T-20 | без `ADMIN_TELEGRAM_ID` бот не стартует (сообщение содержит все отсутствующие переменные); `users` создаётся идемпотентно |
| **CP-3** | после T-22 | все критерии приёмки `docs/tasks/access-control.md` проходятся вручную, включая перезапуск бота между заявкой и решением |
| **CP-4** | после T-23 | README/AGENTS.md не противоречат фактическому поведению |

## 5. Границы

**В объёме:** роутер обновлений + recover, `users` (схема бота), guard,
inline-кнопки регистрации/решения, `ADMIN_TELEGRAM_ID` (+ `.env.example`,
compose), уведомления о решении, README/AGENTS.

**Вне объёма (осознанно, см. ADR-0003):**
- отзыв доступа, разбан, просмотр списков, роли, второй админ;
- версионированные миграции (`PRAGMA user_version` — люк на будущее);
- апгрейд `telegram-bot-api` до v5 (вариант E ADR — отдельный долг);
- обработка групп/каналов (игнорируются), фильтр `From.IsBot` (RR3).

**Запрет регрессий:** поведение одобренного пользователя (`/start`, `/author`,
`/title`, `/result`, `/get`, тексты, reply-клавиатура) не меняется ни в одной
задаче; `books`, `storage.Book`, `finder/`, `cmd/scan`, `cmd/db-create` —
не трогаем.
