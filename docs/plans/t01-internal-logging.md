# T-01. Пакет `internal/logging`: структурированные логи в stdout

- **Приоритет:** P0
- **Оценка:** 0.5 дня
- **Зависит от:** —
- **Блокирует:** T-03, T-04, T-05, T-13
- **Основание:** ADR-0001 §5.6, §5.7

---

## Цель

Создать единую точку настройки логирования для всех трёх бинарей: `slog` пишет
структурированные записи в `os.Stdout`, а стандартный `log`, которым пользуется
`scanner/scan.go`, перенаправляется в `slog`. Ни один компонент не создаёт файлов логов.

## Контекст

Сейчас вывод разнороден: `slog` (без настройки — текст в stderr), стандартный `log`
(с отметками времени в stderr), `fmt.Println`/`fmt.Printf`. `log.log` и
`scan-books.log` в рабочем каталоге — результат ручного redirect-а, а не поведение кода.
Требование FR6: логи только в stdout/stderr, структурированно, видны через
`docker compose logs`.

## Что делать

1. Создать `internal/logging/logging.go`:

   ```go
   // Package logging настраивает структурированное логирование приложения в stdout.
   package logging

   // Setup инициализирует slog-обработчик и перенаправляет стандартный лог в slog.
   func Setup()
   ```

2. Внутри `Setup()`:
   - определить уровень из `LOG_LEVEL` (`debug`|`info`|`warn`|`error`, по умолчанию `info`);
     неизвестное значение → `warn` с предупреждением, запуск продолжается;
   - определить формат из `LOG_FORMAT` (`json`|`text`, по умолчанию `json`);
   - создать `slog.New(<handler>, &slog.HandlerOptions{Level: …})`;
   - `slog.SetDefault(handler)`;
   - `log.SetFlags(0)` и `log.SetOutput(slog.NewLogLogger(handler, slog.LevelInfo))`
     — **это ключевой момент**: существующие `log.Printf` в `scanner/scan.go` и
     `cmd/bot/bot.go` автоматически становятся структурированными записями без правок
     бизнес-кода.

3. Вызвать `logging.Setup()` **первым оператором** в `main()` каждого из трёх бинарей
   (это делается в T-03/T-04/T-05; в T-01 только создаётся пакет).

4. Добавить `internal/logging/logging_test.go`:
   - `Setup()` не паникует при пустом окружении;
   - неизвестный `LOG_LEVEL` и `LOG_FORMAT` не приводят к падению;
   - вывод `log.Printf("x %d", 1)` попадает в stdout (проверка перенаправления через
     подмену `os.Stdout` или буфер `slog`).

## Критерии приёмки

- [ ] `go build ./...` проходит.
- [ ] `go vet ./...` не даёт замечаний на `internal/logging`.
- [ ] `go test ./internal/logging/...` — зелёный.
- [ ] `LOG_FORMAT=text` даёт читаемый вывод, `LOG_FORMAT=json` — валидный JSON построчно.
- [ ] Запись через стандартный `log` попадает в stdout в структурированном виде.

## Риски и примечания

- `slog.NewLogLogger` доступен с Go 1.21; в `go.mod` указано `go 1.24.0` — ограничений нет.
- Не переводить здесь `fmt.Print*` — это отдельная задача T-13, чтобы не смешивать
  обязательный минимум с косметикой.
