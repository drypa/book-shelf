# T-02. Пакет `internal/config`: чтение, валидация, фолбэк на старые имена

- **Приоритет:** P0
- **Оценка:** 1 день
- **Зависит от:** —
- **Блокирует:** T-03, T-05
- **Основание:** ADR-0001 §5.4.2, §5.6

---

## Цель

Единая, явная семантика чтения переменных окружения для всех бинарей:

1. обязательная переменная отсутствует → понятная ошибка и **ненулевой код возврата**;
2. все недостающие переменные сообщаются **одной** ошибкой, а не по одной;
3. для переименованных переменных поддерживается фолбэк на старое имя с предупреждением.

## Контекст

Сейчас `cmd/bot/main.go` делает пять независимых проверок с `return` (код возврата 0!) и
читает переменные через `viper.AutomaticEnv()`, который подразупивает наличие файла
конфигурации, которого нет. Требование FR4: «отсутствие обязательной переменной должно
давать понятную ошибку в логах и корректное завершение процесса (ненулевой код
возврата), а не тихий `return`».

Тот же пакет нужен `cmd/db-create` (ему тоже требуется `DB_DSN`), иначе семантика
фолбэка и формат ошибки разъедутся.

## Переименования (зафиксированы в ADR §5.4.2)

| Старое имя | Новое | Кто читает |
|---|---|---|
| `DB_PATH` | `LIBRARY_DIR` | `bot` |
| `DB_CONNECTION_STRING` | `DB_DSN` | `bot`, `db-create` |
| `BOT_TOKEN` | без изменений | `bot` |
| `HTTP_PROXY` | без изменений | `bot` |
| `SCAN_PARALLELISM` | без изменений | `scan` |

## Что делать

1. Создать `internal/config/config.go` с API:

   ```go
   package config

   // Get возвращает значение primary, если оно задано и непусто.
   // Иначе, если задано legacy, возвращает его и пишет предупреждение
   // об устаревании. Иначе "".
   func Get(primary, legacy string) string

   // Required возвращает значения всех обязательных переменных и ошибку,
   // если хотя бы одна не задана. Ошибка перечисляет ВСЕ отсутствующие
   // переменные: "missing required environment variables: BOT_TOKEN, DB_DSN".
   func Required(names ...string) (map[string]string, error)

   // Lookup — тонкая обёртка над os.LookupEnv для одиночных необязательных
   // переменных (HTTP_PROXY, SCAN_PARALLELISM).
   func Lookup(name string) string
   ```

2. Матрица «primary → legacy» задаётся **внутри пакета** одной таблицей
   (например `map[string]string{"LIBRARY_DIR": "DB_PATH", "DB_DSN": "DB_CONNECTION_STRING"}`),
   а не размазывается по вызывающим бинарям — иначе правило приоритета снова
   начнёт расходиться.

3. Правила `Get`:
   - `primary` задана и непуста → вернуть её; `legacy`, если тоже задана, **игнорируется
     молча** (приоритет нового имени — это задокументированное поведение);
   - `primary` не задана, `legacy` задана → вернуть `legacy` и записать в лог
     `WARN`: `DEPRECATED: DB_PATH is deprecated, use LIBRARY_DIR`;
   - обе не заданы → `""`.

4. Правила `Required`:
   - пробел-only значение считается незаданным (использовать `strings.TrimSpace`);
   - ошибка типа `errors.New` с полным списком отсутствующих имён;
   - предупреждение о legacy выдаётся и здесь.

5. Написать `internal/config/config_test.go` (табличные тесты):
   - `Get` для всех трёх веток (primary / legacy / пусто);
   - приоритет primary над legacy;
   - `Required` перечисляет **все** недостающие переменные;
   - пробел-only значение считается незаданным;
   - предупреждение о legacy пишется ровно один раз.

6. Убедиться, что пакет не тянет `viper`. Удаление `viper` из `go.mod` — в T-03
   (после того, как `cmd/bot` перестанет его использовать).

## Критерии приёмки

- [ ] `go test ./internal/config/...` — зелёный, покрыты все ветки.
- [ ] Пакет не импортирует ничего, кроме стандартной библиотеки и `log/slog`.
- [ ] Матрица переименований объявлена в одном месте пакета.
- [ ] Нет обращения к файлам конфигурации (никакого `.env` внутри Go-кода) —
      это задача compose, а не приложения.

## Риски и примечания

- **Не** помещать в пакет `Load() (*Config, error)` с десятком полей: у бинарей разные
  наборы переменных, общий god-config нарушит SRP и притянет лишние зависимости.
- Фолбэк — временная мера; удаление вынесено в T-16 с явным дедлайном.
