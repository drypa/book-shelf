# T-03. Рефакторинг `cmd/bot/main.go`

- **Приоритет:** P0
- **Оценка:** 1 день
- **Зависит от:** T-01, T-02
- **Блокирует:** T-11, T-12
- **Основание:** ADR-0001 §5.6, §5.8

---

## Цель

Починить ломающий `go vet`/`go test` баг, привести конфигурацию к явной валидации с
ненулевым кодом возврата, переименовать переменные окружения (с фолбэком) и оформить
graceful shutdown по SIGTERM.

## Контекст

Текущий `cmd/bot/main.go` (62 строки) содержит четыре независимых дефекта:

| Строка | Дефект | Последствие |
|---|---|---|
| 34 | `slog.Error("failed to init storage", err)` — `err` голым аргументом | `go vet ./...` и `go test ./...` падают: `cmd/bot [build failed]` |
| 19–28, 41–45, 46–50 | `slog.Error(...); return` | **код возврата 0** при ошибке конфигурации; контейнер «успешно» завершается |
| 18, 24, 41 | проверки вразнобой, `DB_CONNECTION_STRING` проверяется **после** `newStorage()` | ошибка в DSN обнаруживается после `os.Stat` каталога |
| 59–62 | ручной канал `quit`, `db.Close()` в `defer`, нет лога завершения | неявный shutdown, нет подтверждения в логах |

Плюс: `viper.AutomaticEnv()` используется только здесь, хотя файла конфигурации в
проекте нет, — иллюзия конфигурации без её источника.

## Что делать

1. Перестроить `main` в форму «одна точка выхода»:

   ```go
   func main() {
       logging.Setup()
       if err := run(); err != nil {
           slog.Error("bot failed", "err", err)
           os.Exit(1)
       }
   }
   ```

   Все проверки конфигурации — внутри `run()`, без промежуточных `return`.

2. **Починить баг** (критерий приёмки задачи): заменить строку 34 на
   `slog.Error("failed to init storage", "err", err)`.

3. Порядок чтения конфигурации — до любых побочных эффектов:

   ```go
   values, err := config.Required("BOT_TOKEN", "LIBRARY_DIR", "DB_DSN")
   if err != nil {
       return fmt.Errorf("configuration: %w", err)   // все отсутствующие — одним списком
   }
   httpProxy := config.Lookup("HTTP_PROXY")           // необязательная, пустое = без прокси
   ```

   `HTTP_PROXY` читается как необязательная: пустое значение **не должно** превращаться
   в невалидный адрес прокси (edge case задачи). Текущая проверка `if proxy != ""` в
   `cmd/bot/bot.go:43` остаётся как есть.

4. Graceful shutdown — заменить ручной канал на `signal.NotifyContext`:

   ```go
   ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
   defer stop()
   ...
   <-ctx.Done()
   slog.Info("shutdown complete")
   ```

   Убедиться, что `db.Close()` вызывается **явно** до выхода из `run()` (а не только в
   `defer` из `main`), чтобы порядок «отмена контекста → закрытие БД → выход» был
   гарантирован. Существующий механизм выхода горути `processNotifications` через
   `select { case <-ctx.Done(): }` в `cmd/bot/bot.go:75` не трогаем.

5. Убрать `github.com/spf13/viper` из `cmd/bot/main.go`, затем из `go.mod`/`go.sum`
   (`go mod tidy`). Убедиться, что пакет не импортируется больше нигде
   (`grep -rn viper --include=*.go .` должен быть пуст).

6. Не менять: `cmd/bot/bot.go`, `cmd/bot/repository.go`, `cmd/bot/searcher.go`,
   `cmd/bot/storage.go` — бизнес-логика вне объёма (NFR задачи). Исключение —
   `log.Println` в `bot.go:222`, если попадёт в T-13.

## Критерии приёмки

- [ ] `go build ./...` проходит.
- [ ] `go vet ./...` проходит **на всём репозитории**.
- [ ] `go test ./...` не падает на `cmd/bot` (падение в `format/fb2` — предсуществующее,
      см. T-14).
- [ ] Пустой `BOT_TOKEN` → в логах `missing required environment variables: BOT_TOKEN`,
      код возврата **1**.
- [ ] Пустые `BOT_TOKEN` и `DB_DSN` одновременно → в одном сообщении перечислены **оба**.
- [ ] Запуск со старым именем `DB_PATH`/`DB_CONNECTION_STRING` работает, в логах `WARN`
      про устаревание; при одновременно заданных новом и старом имени используется новое.
- [ ] `kill -TERM <pid>` → процесс завершается кодом 0, в логах `shutdown complete`.
- [ ] `grep -rn viper --include=*.go .` пуст; `viper` отсутствует в `go.mod`.

## Риски и примечания

- `log.Fatal(err)` в конце текущего `main` даёт код 1 — это корректно, но после
  рефакторинга единая точка выхода должна покрывать и этот случай, чтобы не осталось
  обходного пути мимо `os.Exit(1)`.
- Не переименовывать переменные в `cmd/bot/storage.go` — параметр там называется `dir`,
  переименование переменной окружения его не касается.
