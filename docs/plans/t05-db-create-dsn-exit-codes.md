# T-05. `cmd/db-create/main.go`: `DB_DSN` из окружения и коды возврата

- **Приоритет:** P0
- **Оценка:** 0.5 дня
- **Зависит от:** T-01, T-02
- **Блокирует:** T-11, T-12
- **Основание:** ADR-0001 §5.1, §5.6

---

## Цель

Сделать путь к базе конфигурируемым (сейчас он зашит как `./db.sqlite3`) и обеспечить
ненулевой код возврата при любой ошибке.

## Контекст

`cmd/db-create/main.go:16`:

```go
db, err := sql.Open("sqlite3", "./db.sqlite3")   // ← путь относительно CWD
```

Две проблемы:

1. Путь не конфигурируется. В контейнере рабочий каталог задаётся образом, а FR7
   требует, чтобы «путь внутри контейнера и путь на хосте задавались через `.env`».
2. Все ошибки обрабатываются как `fmt.Println(err); return` → **код возврата 0**.
   Семь таких мест: `main` (строки 18, 27, 32, 37, 45, 50) и косвенно в `insertBooks`.

Дополнительно: `createTable(err error, db *sql.DB)` принимает `err` параметром и
перезаписывает его — артефакт копипасты, безопасный, но подчистить при
переписывании.

## Что делать

1. Вызвать `logging.Setup()` первым оператором.

2. Заменить путь на переменную окружения `DB_DSN` — **то же имя, что у бота**
   (ADR §5.4.1), чтобы не плодить синонимы:

   ```go
   dsn, err := config.RequireOne("DB_DSN")
   if err != nil {
       slog.Error("configuration", "err", err)
       os.Exit(1)
   }
   db, err := sql.Open("sqlite3", dsn)
   ```

   Если в T-02 API ограничен `Required(names ...string)`, использовать его и взять
   значение из возвращённой карты.

3. `sql.Open` **не** проверяет существование файла и права — он ленивый. Первый реальный
   запрос (`createTable`) это обнаружит. Чтобы оператор получил внятную ошибку, а не
   `unable to open database file`, добавить проверку:

   ```go
   if err := db.Ping(); err != nil {
       slog.Error("cannot open database", "dsn", dsn, "err", err)
       os.Exit(1)
   }
   ```

   Сообщение должно подсказывать проверку `DATA_HOST_DIR`/`DATA_CONTAINER_DIR` и
   `DB_FILE` (риск K1 в ADR §7).

4. Аргумент (каталог с sidecar-файлами) — проверять с кодом 2, как в T-04:

   ```go
   if len(os.Args) < 2 {
       slog.Error("usage: db-create <library-dir>")
       os.Exit(2)
   }
   ```

5. Все `fmt.Println(err); return` заменить на возврат ошибки наружу с
   `os.Exit(1)` (через `run() error`, как в T-03). Ошибки должны логироваться
   структурированно: `slog.Error("db-create failed", "err", err)`.

6. `fmt.Printf("processing %s\n", path)` → `slog.Info("processing sidecar", "path", path)`,
   `fmt.Printf("file %s has no title\n", …)` → `slog.Warn(...)`. Это FR6; объём минимальный
   и относится к тем же семи строкам, что уже меняются.

7. Финальный лог: `slog.Info("db-create finished", "sidecars", len(files))` — по нему
   оператор подтверждает штатное завершение.

8. **Не менять** логику SQL: `CREATE TABLE IF NOT EXISTS books` и
   `INSERT INTO books (...) VALUES (...)` остаются как есть. Идемпотентность
   (`UNIQUE`/upsert) сознательно вне объёма — ADR §6, R11.

## Критерии приёмки

- [ ] `go build ./...`, `go vet ./...` проходят.
- [ ] Без `DB_DSN` → код возврата 1, в логах `missing required environment variables: DB_DSN`.
- [ ] С `DB_DSN`, указывающим на недоступный путь → код возврата 1 с внятным текстом
      (не молчаливый успех).
- [ ] Без аргумента → код возврата 2.
- [ ] Путь к базе **не** зависит от текущего рабочего каталога: запуск из `/tmp` с
      абсолютным `DB_DSN` пишет базу туда, куда указано.
- [ ] Нет ни одного `fmt.Println`/`fmt.Printf` в файле.
- [ ] Схема таблицы `books` не изменилась (сверить с `storage/book.go` и
      `cmd/bot/repository.go`).

## Риски и примечания

- Существующая база (324 МБ) несовместима с изменением схемы — поэтому схема и не
  трогается. Если формат DSN станет `file:`-URI с параметрами (рекомендуется
  `?_journal_mode=WAL`, ADR §7 K4), это параметр подключения, а не схема, и миграции
  данных не требует.
- `insertBooks` открывает транзакцию на каждый архив; при обрыве по середине предыдущие
  архивы уже закоммичены. Это существующее поведение; в README (T-10) описывается порядок
  «остановить бота → удалить базу → пересоздать», а не «догонять частично».
