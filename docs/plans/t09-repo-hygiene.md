# T-09. Гигиена репозитория: `.gitignore` и удаление артефактов

- **Приоритет:** P0
- **Оценка:** 0.5 дня
- **Зависит от:** —
- **Блокирует:** —
- **Основание:** ADR-0001 §1.2, §5.9

---

## Цель

Убрать артефакты данных и сборки из рабочего дерева и закрыть в `.gitignore` те
пути, которые **не** закрыты, не потеряв данные.

## Важное уточнение исходной формулировки

Задача (FR8) утверждает, что `db.sqlite3` (~324 МБ) и бинарь `db-create` «закоммичены в
git». Проверено — **это неверно**:

- `git ls-files` не содержит ни `db.sqlite3`, ни `db-create`, ни `*.log`;
- `git log --all --diff-filter=A --name-only` показывает, что они **никогда** не
  добавлялись в индекс; размер `.git` — **1.9 МБ**;
- `git check-ignore -v` подтверждает: `db.sqlite3` покрыт правилом `*.sqlite3`,
  `log.log`/`scan-books.log` — правилом `*.log`, `.env` — правилом `.env`.

Реально покрытыми **не** являются: `db-create` (корень), `cmd/db-create/db-create`,
`*.zip.json`, каталог `data/`, а также семейство `db.sqlite3-wal`/`-shm`/`-journal`
(правило `*.sqlite3` их не матчит).

## Порядок действий (важно для сохранности данных)

1. **До удаления** убедиться, что данные воспроизводимы:

   ```bash
   ls -la ./data/library/*.zip.json | head     # sidecar-файлы есть?
   ```

   Если sidecar-файлов нет, база восстанавливается только полным повторным
   сканированием (`./scan.sh` + `./db-create.sh`) — это **должно занять часы** на
   библиотеке такого размера. В таком случае удаление `db.sqlite3` откладывается, пока
   бэкап не сделан (ADR §8, фаза 0).

2. Добавить в `.gitignore` (существующие правила `*.log`, `*.sqlite3`, `.env`
   дублировать не нужно):

   ```gitignore
   # ── сборка Go ──────────────────────────────────────────────
   /bot
   /scan
   /db-create
   /cmd/bot/bot
   /cmd/scan/scan
   /cmd/db-create/db-create
   /bin/
   /dist/

   # ── рабочие данные (создаются на хосте, монтируются в контейнеры) ──
   /data/
   *.zip.json
   db.sqlite3*          # -wal, -shm, -journal; правило *.sqlite3 их НЕ покрывает

   # ── окружение ──────────────────────────────────────────────
   .env
   .env.*
   !.env.example
   ```

3. Удалить с диска (после шага 1 и при наличии бэкапа вне репозитория):

   ```bash
   rm -f ./db-create ./cmd/db-create/db-create ./log.log ./scan-books.log
   # db.sqlite3 — отдельным шагом в самом конце миграции (ADR §8, фаза 6)
   ```

4. Верифицировать, что в индексе чисто и новые пути закрыты:

   ```bash
   git ls-files | grep -E 'sqlite3|\.log$|^db-create$' ; echo "код: $?"   # ожидается не 0
   git check-ignore -v data/library/a.zip.json data/db/db.sqlite3-wal db-create cmd/db-create/db-create
   git status --porcelain
   ```

5. Обновить `AGENTS.md`, если там есть утверждения о наличии `db.sqlite3` в репозитории
   (проверить; правки в целом — T-11).

## Критерии приёмки

- [ ] `git ls-files` не содержит артефактов данных и сборки.
- [ ] `git check-ignore -v` подтверждает игнор для: `db-create`,
      `cmd/db-create/db-create`, `data/library/a.zip.json`, `data/db/db.sqlite3`,
      `data/db/db.sqlite3-wal`, `data/db/db.sqlite3-shm`, `log.log`, `.env`,
      `scan-books.log`.
- [ ] `.env.example` **не** игнорируется (правило `!.env.example`).
- [ ] `db.sqlite3` либо удалён (после бэкапа), либо остаётся и явно отмечен как
      подлежащий удалению в финальной фазе миграции.
- [ ] `git status --porcelain` не показывает новых непроиндексированных артефактов
      после `docker compose up` (проверяется в T-12).

## Риски и примечания

- `db.sqlite3` — единственный артефакт, удаление которого **необратимо** без бэкапа;
  поэтому в этой задаче его удаление допускается только при подтверждённой
  воспроизводимости и сделанном бэкапе. Это ADR §7, риск K13.
- `data/` в `.gitignore` критичен: туда оператор кладёт ZIP-архивы, и без правила первый
  же `git add -A` попытается закоммитить библиотеку.
- Файл `format/fb2/fb2_test.go` модифицирован в рабочем дереве **не этой задачей** —
  не затереть и не коммитить вместе с гигиеной (см. T-14).
