# T-10. `README.md` — инструкция по развёртыванию

- **Приоритет:** P1
- **Оценка:** 1 день
- **Зависит от:** T-07, T-08
- **Блокирует:** T-12
- **Основание:** ADR-0001 §5.10

---

## Цель

Дать оператору путь от чистого хоста до работающего бота, не читая кода, и явно
предупредить о двух известных ловушках пайплайна.

## Контекст

Сейчас единственный документ — `AGENTS.md`, и он написан для разработчика, а не для
оператора. FR9 требует README с инструкцией по развёртыванию, описанием переменных и
скриптов, **двумя** предупреждениями и командами диагностики.

Оба предупреждения — про реальные, проверенные риски:

- `scan` монтирует каталог библиотеки **на запись** и создаёт рядом с архивами
  `*.zip.json`, меняя права/владельца на хосте (FR7, риск K6/K11);
- повторный `db-create` **дублирует строки**, потому что вставка идёт без
  `UNIQUE`-ограничения и без upsert-а (риск K3).

## Структура README

### 1. Что это

Кратко: Telegram-бот ищет FB2-книги в ZIP-архивах; индексация офлайновая, тремя
шагами. Схема пайплайна в виде текста или ASCII-блока.

### 2. Требования

- Docker Engine **23+** (нужен BuildKit для кэш-монтиров в `Dockerfile`);
- Docker Compose **v2** (используется синтаксис `name:`, `profiles`, `run --rm`);
- ничего больше: Go, sqlite3, jq на хосте **не нужны**.

### 3. Первичное развёртывание (шаги по порядку)

1. `mkdir -p data/library data/db` — каталоги создаются **вручную** (решение заказчика).
   Пояснить, почему: Docker иначе создаст их сам от `root` (риск K1).
2. Положить `*.zip`-архивы в `data/library`.
3. `cp .env.example .env`, заполнить `BOT_TOKEN`.
4. `sudo chown -R 10001:10001 data/library data/db` — **объяснить зачем**: контейнеры
   работают непривилегированно (uid 10001); либо задать в `.env` свои
   `SCAN_USER_ID`/`SCAN_GID`.
5. `./build.sh`
6. `./up.sh`
7. Проверка: `docker compose ps` → бот `Up`; `/start` в Telegram.

### 4. Переменные окружения

Таблица из ADR §5.4.1: имя | обязательность | значение по умолчанию | назначение.
Отдельно пояснить инвариант `DB_DSN = ${DATA_CONTAINER_DIR}/${DB_FILE}` и то, как
включить DSN-параметры (раскомментировать `DB_DSN` в `.env`).

### 5. Скрипты

Таблица: скрипт | что делает | когда применять. Отдельно отметить, что `build.sh`
использует `--profile tools` и **почему** это обязательно — иначе оператор «оптимизирует»
и сломает сборку.

### 6. ⚠️ Предупреждение: `scan` изменяет каталог библиотеки

- Монтирует `LIBRARY_HOST_DIR` в режиме **чтение/запись**;
- создаёт рядом с каждым архивом `<archive>.zip.json`;
- файлы и каталог на хосте получают владельца контейнера (10001 или root, если задан
  `SCAN_USER_ID=0`);
- последствие: каталог библиотеки перестаёт быть «только для чтения» — нельзя
  синхронизировать его с внешним источником без учёта sidecar-файлов.

### 7. ⚠️ Предупреждение: повторный `db-create` дублирует строки

- Почему: `INSERT INTO books …` без `UNIQUE`-ограничения и без upsert-а;
- что будет: поиск вернёт дубликаты, а `/get N` может отдать не ту книгу;
- **рекомендуемый порядок переиндексации:**

  ```bash
  docker compose stop bot        # снять читателей с базы
  ./scan.sh                      # если изменилась библиотека; иначе пропустить
  rm -f ./data/db/db.sqlite3*    # сбросить базу целиком (важно: и -wal, и -shm)
  ./db-create.sh
  ./up.sh
  ```

- подчеркнуть: `db-create.sh` **не** является командой «обновить индекс».

### 8. Диагностика

| Симптом | Команда / действие |
|---|---|
| бот не поднялся | `docker compose ps` → ожидается `Exited (1)`; `docker compose logs bot` |
| «нет книг» | `./scan.sh` — смотреть `failed to process archive …` в логах |
| каталог пуст | `ls -la data/library`; `docker compose run --rm scan` (проверить путь внутри контейнера) |
| прокси не работает | `HTTP_PROXY` берётся **только** из `.env`; экспорт в shell хоста не действует |
| ошибка SQLite | `docker compose run --rm db-create` — код возврата и текст в логах |
| переустановить | `docker compose down` (Compose v5: без `-q`) |

Плюс ручная проверка UC6: `/start` → `/author …` → `/get 1`.

### 9. Бэкап и восстановление

- `sqlite3 data/db/db.sqlite3 ".backup '/backup/book-shelf-$(date +%F).db'"` — безопасно на
  горячей базе;
- альтернатива: копирование файла при остановленном боте;
- восстановление: положить файл на место, `docker compose restart bot`.

### 10. Приватность и безопасность

- `.env` не коммитится; в образы секреты не попадают;
- контейнеры непривилегированные, `cap_drop: ALL`, `read_only`;
- состояние поиска пользователей живёт **только в памяти** и теряется при перезапуске
  бота (существующее поведение).

  `internal/config`) — это задача `AGENTS.md`.
