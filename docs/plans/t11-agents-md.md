# T-11. Обновление `AGENTS.md` под новое окружение

- **Приоритет:** P1
- **Оценка:** 0.5 дня
- **Зависит от:** T-03, T-05, T-08
- **Блокирует:** —
- **Основание:** ADR-0001 §5.1 (файл в структуре), §10

---

## Цель

Привести `AGENTS.md` в соответствие с новой схемой окружения и разграничить audiences:
`AGENTS.md` — для разработчика, `README.md` — для оператора.

## Контекст

`AGENTS.md` содержит утверждения, которые после T-03/T-05/T-08 станут неверны:

| Место | Сейчас | Стало |
|---|---|---|
| Шапка | «No README — this file is the only guide» | README появился; ссылка на него |
| Раздел «Bot environment variables» | `DB_PATH` — «directory containing the `.zip` archives», `DB_CONNECTION_STRING` | `LIBRARY_DIR`, `DB_DSN`; старые имена — только как фолбэк |
| Там же | «All read via `viper.AutomaticEnv()`… no `.env` file loading» | viper удалён; конфигурация приходит из окружения **контейнера**, а `.env` читает compose |
| Там же | «Because the proxy is read as a bare `HTTP_PROXY`, any proxy exported in the shell silently routes Telegram traffic through it» | В контейнер попадает **только** значение из `.env`; предупреждение больше не актуально (ADR §7, K7) |
| Раздел «Pipeline» | `go run ./cmd/scan <lib-dir>`, «`./db.sqlite3`, relative to the current working directory» | `docker compose --profile tools run --rm scan` / `db-create`; `DB_DSN` из окружения |
| Там же | «Re-running `db-create` duplicates rows… Wipe the DB and rescan» | сохранить, дополнив точными командами из README §7 |
| Раздел «Build / verify» | «Known pre-existing vet failure… `cmd/bot/main.go:34`» | устранён; заменить на фактический статус проверок |
| Раздел «Build / verify» | CI только `go build -v ./cmd/bot/...` | дополнить указанием на `--profile tools build` (ADR §4, E3) |
| Файл в целом | нет упоминаний Docker | добавить раздел про контейнерный деплой и ссылку на `docs/adr/0001` |

## Что делать

1. Обновить шапку: добавить строку «Инструкция для оператора — в `README.md`;
   техническое решение — `docs/adr/0001-docker-compose-deployment.md`».

2. Переписать раздел о переменных окружения: новая таблица имён, правило фолбэка на
   старые имена, ссылка на `.env.example` как на единственный источник правды.

3. Переписать раздел «Pipeline»: для каждого шага указать и ручной запуск бинаря
   (для разработчика), и контейнерный запуск через скрипты (для проверки в среде,
   приближенной к продовой).

4. Добавить краткий раздел «Контейнерный деплой»:

   ```bash
   ./build.sh    # docker compose --profile tools build  (--profile обязателен)
   ./up.sh       # только бот
   ./scan.sh     # разово, RW в каталог библиотеки
   ./db-create.sh# разово, дублирует строки при повторном запуске
   ```

   с предупреждениями из README §6–§7 (кратко, со ссылкой на него).

5. Обновить раздел «Build / verify»:

   ```bash
   go build ./...
   go vet ./...
   go test ./archive/... ./finder/... ./storage/...
   go test ./internal/...
   ```

   Отдельно зафиксировать известное предсуществующее падение
   `format/fb2.TestReadFb2` (негерметичный тест с абсолютным путём вне репозитория) —
   чтобы его не приняли за регрессию (ADR §7, K9; чинится в T-14).

6. Убрать или переформулировать утверждения о «Known pre-existing vet failure» — после
   T-03 их больше нет.

7. Не меняять разделы «Bot command flow», «Layout notes» (про `storage/book.go`,
   `finder/` legacy, `format/fb2`) — они остаются актуальными.

## Критерии приёмки

- [ ] В `AGENTS.md` нет упоминаний `DB_PATH` и `DB_CONNECTION_STRING` как актуальных
      имён (допустимо упоминание только как «устаревшее, поддерживается фолбэком»).
- [ ] В `AGENTS.md` нет упоминаний `viper`.
- [ ] Утверждение про «only guide» заменено ссылкой на README.
- [ ] Описан запуск пайплайна и через бинари, и через скрипты.
- [ ] Раздел «Build / verify» соответствует фактическому состоянию репозитория
      (проверено `go build ./... && go vet ./...`).
- [ ] Указано требование `--profile tools` для сборки.
- [ ] Нет утверждений, противоречащих README.

## Риски и примечания

- `AGENTS.md` — единственный файл, который читает агент при работе в репозитории:
  ошибка здесь дороже, чем где-либо ещё. Проверять построчно.
- Правки в `AGENTS.md` логически зависят от T-03/T-05/T-08, но текст можно
  подготовить заранее — финальная сверка после завершения зависимостей.
