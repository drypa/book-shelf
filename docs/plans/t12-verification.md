# T-12. Верификация и приёмка (UC1–UC6)

- **Приоритет:** P1
- **Оценка:** 1 день
- **Зависит от:** T-03, T-04, T-05, T-06, T-07, T-08, T-09, T-10
- **Блокирует:** T-16
- **Основание:** ADR-0001 §8 (фаза 5), §11

---

## Цель

Доказать, что решение работает: код собирается и проходит проверки, а контейнерный
деплой воспроизводится по README и закрывает все сценарии использования задачи.

## Контекст

Приёмка ручная, автотесты для деплоя не требуются (решение заказчика). Но
существующие `go vet`/`go build`/тесты должны проходить — это отдельный критерий.

## Часть A. Проверки Go

```bash
go build ./...                                     # ожидается: пусто, код 0
go vet ./...                                       # ожидается: пусто, код 0
go test ./archive/... ./finder/... ./storage/... ./internal/...
go test ./...                                      # cmd/bot больше НЕ падает
```

- [ ] `go build ./...` — код 0.
- [ ] `go vet ./...` — код 0 **на всём репозитории** (критерий задачи; T-03).
- [ ] `go test ./...` не содержит `cmd/bot [build failed]`.
- [ ] Известное падение `format/fb2.TestReadFb2` зафиксировано как предсуществующее
      (ADR §7, K9), а не замаскировано правкой теста «на бегу».

## Часть B. Проверки образов

```bash
docker compose --profile tools build
docker images | grep book-shelf                    # три образа
docker run --rm --entrypoint id book-shelf-bot:latest    # uid=10001
docker run --rm book-shelf-db-create:latest /каталог     # usage, код 2
```

- [ ] Собираются ровно три образа: `book-shelf-bot`, `book-shelf-scan`, `book-shelf-db-create`.
- [ ] В финальных образах нет ни `.git`, ни `.env`, ни `docs`, ни `db.sqlite3`.
- [ ] Контейнеры работают непривилегированно.

## Часть C. Сценарии UC1–UC6

| UC | Шаги | Ожидание |
|---|---|---|
| **UC1** первичное развёртывание | `mkdir -p data/library data/db`; положить `.zip`; `cp .env.example .env`; вписать `BOT_TOKEN`; `./build.sh`; `./up.sh`; `docker compose ps`; `/start` в Telegram | бот `Up`; отвечает; `scan`/`db-create` не запущены |
| **UC2** пополнение | положить новый `.zip`; `./scan.sh`; `./db-create.sh`; найти книгу; `/get 1` | логи в stdout; новая книга находится и скачивается |
| **UC3** повторное развёртывание | `./build.sh`; `./up.sh` на существующих данных | данные не перезаписаны, переиндексации нет |
| **UC4** с прокси | задать `HTTP_PROXY` в `.env`; `./up.sh` | бот работает через прокси; без переменной — напрямую |
| **UC5** ошибка конфигурации | очистить `BOT_TOKEN`; `./up.sh`; `docker compose ps`; `docker compose logs bot` | контейнер завершился с кодом 1, в логах `missing required environment variables: BOT_TOKEN`; **нет** бесконечного restart (пять попыток и стоп) |
| **UC6** ручная проверка | `docker compose ps`; `docker compose logs bot`; `/start`; `/author …`; `/get 1` | всё работает, логи содержат сообщение о запуске |

## Часть D. Нефункциональные проверки

- [ ] **Graceful shutdown:** `docker compose stop bot` → контейнер завершается кодом 0
      (не 137), в логах `shutdown complete`.
- [ ] **Коды возврата:** `docker compose run --rm scan /несуществующий` → ненулевой код;
      `./scan.sh` пробрасывает его наружу.
- [ ] **Нет файлов в контейнере:** `docker compose exec bot ls -la /` → нет `log.log`;
      `docker compose run --rm scan` с `read_only: true` отрабатывает успешно.
- [ ] **Логи в stdout:** `docker compose logs scan` содержит `processing archive …` и
      `scan finished`; файлов `*.log` в рабочем дереве репозитория не появилось.
- [ ] **Гигиена:** после всех запусков `git status --porcelain` не показывает новых
      непроиндексированных артефактов.
- [ ] **Таймзона:** `TZ=Europe/Moscow` в `.env` влияет на метки времени в логах
      (значит, `tzdata` на месте).

## Часть E. Эдже-кейсы задачи

- [ ] `scan` на каталоге с битыми архивами → код 0, ошибки по каждому архиву в логах.
- [ ] `db-create` при отсутствии sidecar-файлов → внятная ошибка с подсказкой
      «сначала запустите ./scan.sh», ненулевой код.
- [ ] Несуществующий каталог библиотеки на хосте → приложение сообщает, что архивов не
      найдено (а не молчит), плюс проверка, что Docker создал пустой каталог от `root`
      (риск K1) и что это диагностируется.
- [ ] Пустой `HTTP_PROXY` не превращается в невалидный адрес прокси.
- [ ] Запуск со **старыми** именами `DB_PATH`/`DB_CONNECTION_STRING` (вне compose) работает,
      в логах `WARN` про устаревание.

## Артефакт

Зафиксировать результат в PR-описании или коммите приёмки: список пройденных пунктов +
всё найденное несоответствие. Расхождения → новые задачи, а не «поправим по ходу».

## Риски и примечания

- UC1 требует реального `BOT_TOKEN`; если его нет, проверять UC5 (ошибка
  конфигурации) и UC6 (управление через тестовый токен/логи), а UC1 отметить как
  «ожидает токена оператора».
- Не пропускать эдже-кейс с пустым каталогом библиотеки: это самая вероятная поломка
  первого деплоя (риск K1).
