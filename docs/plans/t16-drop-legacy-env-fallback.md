# T-16. Удаление фолбэка на старые имена переменных

- **Приоритет:** P2
- **Оценка:** 0.5 дня
- **Зависит от:** T-12
- **Блокирует:** —
- **Основание:** ADR-0001 §5.4.2, §6 (R16)

---

## Цель

Убрать поддержку `DB_PATH` и `DB_CONNECTION_STRING`, объявленную временной мерой, чтобы
устаревшая конфигурация перестала работать незаметно.

## Контекст

Фолбэк введён осознанно (ADR §5.4.2): он защищает существующие ручные запуски, которые
невозможно адаптировать заранее. Но у любого compatibility shim есть срок годности —
иначе «временно поддерживаемое» имя становится постоянным контрактом, о котором
забывают.

Условие запуска: приёмка (T-12) пройдена, деплой по compose использует только новые
имена минимум один цикл эксплуатации.

## Что делать

1. Подтвердить, что фолбэк больше не нужен:

   ```bash
   grep -rn "DB_PATH\|DB_CONNECTION_STRING" --include=* . \
     | grep -v '^./.git/'
   ```

   Ожидаемые места: `internal/config/config.go` (матрица), `internal/config/config_test.go`,
   `AGENTS.md` (упоминание устаревания). Если что-то ещё найдено — сначала перевести.

2. Удалить из `internal/config`:

   - записи `LIBRARY_DIR → DB_PATH` и `DB_DSN → DB_CONNECTION_STRING` из матрицы;
   - упростить сигнатуру, если она станет избыточной: `Get(name)` вместо
     `Get(primary, legacy)`; удалить логику `WARN`;
   - удалить тесты на legacy-ветку, **оставив** тесты на primary-ветку и на
     «не задано».

3. Обновить `AGENTS.md`: убрать упоминание фолбэка, оставить явное предупреждение, что
   старые имена больше не поддерживаются и запуск с ними завершится с кодом 1.

4. Обновить README: в таблице переменных остаются только новые имена; добавить строку в
   раздел миграции/обновления: «после версии X имена `DB_PATH` и
   `DB_CONNECTION_STRING` больше не поддерживаются — переименуйте в `LIBRARY_DIR` и
   `DB_DSN`».

5. Зафиксировать решение отдельным ADR (ADR-0002, `docs/adr/`): статус, дата, причина
   удаления, что именно удалено. Это причина существования ADR в проекте — решение
   должно быть записано, а не только сделано.

## Критерии приёмки

- [ ] `grep -rn "DB_PATH\|DB_CONNECTION_STRING"` в коде, скриптах, compose и `.env.example`
      даёт только упоминание в ADR/T-16 как историческом факте.
- [ ] Запуск с `DB_PATH=… BOT_TOKEN=… DB_DSN=…` и **без** `LIBRARY_DIR` завершается
      кодом 1 с `missing required environment variables: LIBRARY_DIR`.
- [ ] `go build ./...`, `go vet ./...`, `go test ./internal/...` проходят.
- [ ] `AGENTS.md` и README не обещают поддержку старых имён.
- [ ] Существует ADR с решением об удалении.

## Риски и примечания

- Выполнять **не раньше**, чем пройден цикл эксплуатации на новых именах; если фолбэк
  удалён слишком рано, а где-то остался systemd-юнит со старым именем, сервис молча
  перестанет стартовать. Компенсирующая мера: `WARN`-лог перестаёт появляться, зато
  появляется явная фатальная ошибка с именем переменной.
- Не удалять фолбэк «заодно» с другими рефакторингами — только отдельным коммитом,
  чтобы его можно было откатить независимо.
